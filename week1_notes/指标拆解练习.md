# 指标拆解练习（第1周 · 前3天任务）

> **练习目的**：不写代码，先学会「问对问题」。  
> **核心指标**：支付转化率（Payment Conversion Rate）  
> **假设场景**：某日 / 某周支付转化率环比下降 **5%**（例如从 7.00% → 6.65%）。  
> 下面这套「拆解顺序」就是面试时业务思维的原始素材——它能证明你不是「一上来就甩锅渠道 / 价格」的直觉型选手。

---

## 一、先把指标定义清楚（口径优先）

> 很多「指标下跌」的追问，第一步其实是在问口径。第8周面试追问 1「有没有可能是数据口径或时间周期导致的」就是这里埋的伏笔。

**支付转化率（本项目的口径）**

```
支付转化率 = 统计周期内发生过「购买(buy)」的独立用户数
          / 统计周期内发生过「浏览(pv)」的独立用户数
```

- 分子：买过东西的人（`behavior_type = 'buy'` 的去重 user_id）
- 分母：来过的人（`behavior_type = 'pv'` 的去重 user_id）
- 用「用户口径」而非「事件口径」，因为业务上更关心「多少人被转化」，而非「多少次点击被转化」。

**为什么先定义口径**：同一指标不同口径能差好几倍。不先对齐定义，后面的拆解全是无用功。

---

## 二、拆解顺序（核心 · 按优先级）

### 第 0 步：先排除「假下跌」（证伪）

> 顺序之所以把这一步放最前，是因为 5% 的波动很可能根本不是业务问题。

1. **时间周期对齐**：环比是不是拿对了区间？有没有把大促日 / 双11 / 周末基线混进来？
2. **数据完整性**：埋点是否丢失？ETL 是否延迟（当天数据没跑全）？去重口径是否被改过？
3. **节假日 / 季节基线**：转化率本来就周末高、工作日低，先确认是不是「结构性波动」而非「真下跌」。

→ 若第 0 步发现是数据 / 周期问题，**先修数据，不往下拆**。

### 第 1 步：整体漏斗定位（定位「掉在哪一段」）

把转化拆成标准漏斗，逐段算转化率，看下跌发生在哪一段：

```
浏览(pv) → 收藏(fav) → 加购(cart) → 购买(buy)
```

| 漏斗段     | 转化率            | 关注点          |
| ------- | -------------- | ------------ |
| 浏览 → 收藏 | fav用户 / pv用户   | 内容 / 商品吸引力   |
| 收藏 → 加购 | cart用户 / fav用户 | 决策阻力         |
| 加购 → 购买 | buy用户 / cart用户 | 支付 / 价格 / 库存 |

→ 假设定位到 **收藏 → 加购** 这段掉得最多，就锁定这一段继续下钻。

### 第 2 步：按维度下钻（定位「谁 / 哪在掉」）

带着第 1 步锁定的漏斗段，从 4 个维度交叉看：

1. **时间维度**：是哪一天 / 哪一周掉的？周末峰值后回落，还是某个异常日（如发版、事故）？
2. **用户分层**：新客 vs 老客？RFM 高价值 vs 一般 vs 流失用户？是不是某一层整体下滑？
3. **渠道维度**：搜索 / 推荐 / 活动 / 外部投放，各自转化率是否某一渠道单独掉了？
4. **商品品类维度**：哪个 `category_id` 类目掉了？是否缺货、涨价、上新导致？

→ 假设下钻结论：**掉落集中在「新客 + 服饰类目 + 收藏→加购段」**。

### 第 3 步：归因 → 假设 → 验证

- **归因**：收藏后用户缺乏「降价 / 库存 / 到货」提醒，导致收藏未购流失。
- **可执行的建议**：对「收藏未购」人群在 **48 小时内** 推送定向优惠券。
- **验证**：用 A/B Test（实验组推送券 / 对照组不推），看该段转化率提升是否显著。

---

## 三、为什么是这个顺序（方法论小结）

```
证伪(排除噪声)  →  漏斗定位(掉在哪)  →  维度下钻(谁/哪在掉)  →  归因+假设+验证
```

- 先证伪：避免把数据延迟当成业务事故。
- 再漏斗：用最少动作锁定问题环节。
- 再下钻：用维度交叉把问题收敛到具体人群 / 品类。
- 最后归因：此时的结论才有「可执行的建议」和「可验证的方法」。

---

## 四、面试 30 秒版（照着背）

> 「支付转化率掉了 5%，我不会先下结论。第一步先排除是不是数据口径或时间周期导致的假下跌；确认是真跌后，用漏斗定位它掉在『收藏→加购』这一段；再按时间、用户分层、渠道、品类四个维度下钻，发现集中在新客和服饰类目；最后归因是收藏后缺提醒，建议对收藏未购人群 48 小时内推券，并用 A/B Test 验证。」
